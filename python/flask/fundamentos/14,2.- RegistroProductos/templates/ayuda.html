Centro de Ayuda

Aprende los fundamentos del patrón de desarrollo web Post → Redirect → Get (PRG) en Flask.

Glosario de Conceptos Aprendidos

Concepto Función / Descripción
GET Solicitar o recuperar de forma segura una página o recurso desde el servidor [1].
POST Enviar información de forma activa al servidor (ej. datos de un formulario) [1].
request.form Diccionario especial de Flask para capturar los datos enviados mediante un método POST [1].
redirect() Instrucción que ordena al navegador del usuario realizar una nueva petición hacia otra ruta diferente [1].
render_template() Procesa y dibuja una plantilla HTML combinando lógica de Python con Jinja2 [1].

¿Por qué usar redirect() tras un POST?

Si renderizas una plantilla de manera directa luego de un POST y el usuario actualiza la página (F5), el navegador reenvía los datos. En apps reales, esto genera **registros, cobros o pedidos duplicados**.

Render vs Redirect

render_template() procesa y muestra el HTML en la ruta actual. En cambio, redirect() le exige al navegador hacer una petición completamente nueva (tipo GET) hacia una URL distinta.

¿Por qué request.form queda vacío?

Porque una redirección inicia un ciclo de solicitud nuevo e independiente. Los datos del formulario viajan en la petición POST inicial, pero no se transportan automáticamente al posterior viaje en formato GET.

El problema pendiente

Como las solicitudes web no guardan memoria por defecto, requerimos mecanismos externos para transferir información entre rutas tras un desvío (como el nombre del producto). Esto se resolverá implementando persistencia de datos (sesiones o bases de datos).
